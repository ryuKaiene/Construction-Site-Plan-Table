# 開発

引数：今週の週次ノートの候補番号（省略時は推薦テーマ。ただし利用者の承認が確認できない場合は尋ねる）。

## 1. 着手前の合意

- 完成の定義（1〜3行）、想定利用者、保存場所を確認する。
- 作業量がM以上なら、セッションごとの区切り（設計／実装／検証）を示す。
- 既存の成果物の育成なら、その台帳と評価履歴を先に読む。

## 2. 実装

- `CLAUDE.md` の技術方針と機密規則に従う。
- 成果物は専用のリポジトリまたはフォルダに置く。既存ファイルの変更、外部送信、公開、費用の発生は事前承認を得る。
- 実データが必要なときは、架空のデータで作り、実データの投入は利用者が行う。

## 3. 検証

- 実際に動かして確認する。確認できなかった点は隠さず記録する。
- 利用者が最初に試す手順を3行以内で用意する。

## 4. 区切り

- セッションを終えるときは、週次ノートの「開発内容」に進捗と次の一手を書く。
- 完成したら `/weekly-record` を実行する。
- 利用枠に余力があり、価値が上がる作業（テスト、手順書、別案の検証）があれば `余力キュー.md` に積む。無理に作業を増やさない。
